02 · TEAM THESIS

Team Thesis

AI-assisted RFI triage can improve construction information flow by helping project teams identify urgent RFIs earlier, route them to the appropriate responder, and recognize repeated or related questions before delays grow.

In Demo 1, our first RFI triage agent showed potential but also revealed important limitations. The agent performed well in identifying responders, but it tended to overestimate urgency and had difficulty recognizing repeated RFIs when earlier project context was unavailable.

For Demo 2, we use real construction-phase RFIs from the UW Haggett Hall project to test whether an improved version of the agent can classify RFI priority more accurately and consistently.

Our current project data shows an average RFI processing time of approximately 7.3 days. We are testing whether better identification of urgent RFIs could contribute to reducing average processing time by approximately 10%.

03 · PROJECT LENS

Project Lens

Beginning with Demo 2, our project lens uses real construction-phase RFI data from the University of Washington Haggett Hall project managed by Andersen Construction.

The dataset includes RFIs #25 through #55, including follow-up RFIs such as 26.1, 27.1, and 30.1. In total, the available dataset contains 35 RFIs created between February 12 and April 9, 2025.

Unlike the Brush Creek dataset used in Demo 1, these are actual construction-phase RFIs. The log includes contractor questions, responders, due dates, responses, schedule and cost impacts, and processing-time information.

For formal Demo 2 evaluation, we selected 10 RFIs representing different urgency levels, technical issues, and follow-up conditions.

Andersen Construction's original response windows are used as our priority ground truth. RFIs with response windows of 2 to 4 days are Priority 1, 7 to 9 days are Priority 2, and 13 days or more are Priority 3.

The Haggett Hall dataset is real project data and is not synthetic. It was shared with GC Team 7 for this UW course project.

04 · COORDINATION POSTURE

Coordination Posture

→

reviews the issue, uses AI assistance to organize and triage the RFI, verifies the result, and routes the RFI through the appropriate contractual channel.

→
03

Design Team / Owner Representative

receives the RFI, interprets the request, and provides clarification or a response.

Information artifacts in scope

The main information artifact is the Request for Information (RFI). Additional artifacts may include the original contractor question, previous RFIs, relevant project drawings, specifications, and supporting project documents.

AI coordination posture

AI is used as a triage and organization assistant for RFIs. It may classify urgency, identify the likely responder, recognize follow-ups, and organize relevant information.

Human users remain responsible for reviewing the result before action is taken. The agent should never answer as if it were the architect or engineer, invent drawing or specification references, or bypass the contractual communication channel.

08 · COORDINATION DEMO #2

RFI Triage Agent · Haggett Hall

Demo 2 builds on our first RFI triage agent using real construction-phase RFI data from the UW Haggett Hall project. The main experiment tests whether Agent v2 can classify RFI priority more accurately than a simple keyword-based rule.

What Changed Since Demo 1

Demo 1 used the Brush Creek dataset and revealed limitations including over-flagged urgency, inconsistent priority calibration, and difficulty recognizing follow-up RFIs.

For Demo 2, we switched to 35 real construction-phase RFIs from the UW Haggett Hall project. Ten RFIs were selected for formal evaluation, and Agent v2 uses the full verbatim RFI questions rather than shortened paraphrases.

Earlier RFIs are also provided as context so the agent can identify follow-up questions such as RFI 27.1 and RFI 30.1.

FAILURE ANALYSIS

What We Learned

CLASSIFICATION FAILURES

Stable does not necessarily mean accurate

The agent gave consistent priority outputs across both runs, but those outputs still differed from the project-log ground truth for several RFIs. The next iteration needs better calibration to the actual response windows used by the GC.

GC ROLE BOUNDARIES

Crossed-a-Line Check

We separately review whether the agent answers as if it were the architect or engineer, invents drawing or specification numbers, or routes an RFI outside the contractual communication channel.

WHAT THIS SAYS ABOUT OUR THESIS

Agent v2 improved consistency and follow-up detection, but priority classification remains the key limitation.

The Demo 2 result does not support the claim that the current Agent v2 prioritizes RFIs better than the simple keyword baseline. However, the negative result identifies a clear next step: calibrating priority directly to real project response windows while preserving the improvements in routing, follow-up detection, and structured triage.
